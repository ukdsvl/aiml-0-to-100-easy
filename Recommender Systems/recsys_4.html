Reinforcement Learning, Bandits, and Recommender Systems

Primary references:

  • Netflix: GenRec — Towards LLM-Native Recommendation
  • Google Research: Retrieve-for-Train
  • Google Research: The sleep framework for continual learning

Overview

Recommender systems are not a single model. They are multi-stage decision systems that interpret user intent, retrieve candidates, enforce constraints, rank items, diversify results, and learn from feedback.

This document covers:

  • Recommender-system funnels.
  • Candidate generation and ranking.
  • Multi-objective learning.
  • Multi-armed and contextual bandits.
  • Position and selection bias.
  • Diversity and exploration.
  • Set-level retrieval.
  • LLM-native recommendation.
  • Continual learning.

Part 1: Recommender-System Foundations

Module 1: The Recommendation Problem

Given a user $u$, interaction history $H$, context $\tau$, and time $t$, a recommender produces a ranking $\pi$ over catalog items $C$:

\[(u,\tau,t,H) \rightarrow \pi\]

where $\pi(i)$ is the position assigned to item $i$.

The objective is expected long-term user utility, not merely immediate clicks or short-term engagement. Netflix describes this as a proxy for satisfaction and retention.

Module 3: Candidate Generation

Candidate generation retrieves hundreds or thousands of potentially relevant items from a catalog that may contain millions.

Method Mechanism Strength
Collaborative filtering Learns from user-item interactions Captures behavioral similarity
Content-based filtering Matches item metadata and user profile Works for cold-start items
Matrix factorization Learns user and item latent factors Compact personalized representation
ANN retrieval Searches embedding space Scales to large catalogs

Approximate Nearest Neighbor, or ANN, search commonly uses Hierarchical Navigable Small World graphs, Product Quantization, or inverted-file indexes. These trade exact recall for lower latency and memory use.

Module 4: Filtering and Diversification

After retrieval, the system applies business and policy constraints:

  • Remove out-of-stock items.
  • Remove age-restricted or region-blocked content.
  • Enforce content-mix rules.
  • Add freshness boosts.
  • Prevent redundant recommendations.
  • Introduce exploration.

Over-personalization can create echo chambers. Diversity constraints, such as Maximal Marginal Relevance, and bandit exploration help broaden exposure.

Transformer-based rankers use self-attention to model mutual influence among items in a candidate list. Wide-and-Deep networks combine memorization components with generalized neural components. Deep Listwise Context Models, or DLCM, model list-level context during ranking.

Module 6: Multi-Task Learning

Recommenders must balance competing objectives:

  • Click-through rate, or CTR.
  • Conversion rate, or CVR.
  • Watch time.
  • Completion rate.
  • Saves or adds to list.
  • Long-term retention.
  • Revenue.
  • Satisfaction.

Multi-gate Mixture-of-Experts, or MMoE, uses multiple expert sub-networks and task-specific gating networks. This helps balance conflicting objectives without forcing full negative transfer between tasks.

Module 7: Bayesian Personalized Ranking

Bayesian Personalized Ranking, or BPR, optimizes matrix-factorization models for implicit feedback using pairwise ranking loss.

For a user $u$, preferred item $i$, and non-preferred item $j$:

\[\mathcal{L}_{BPR} = -\sum_{(u,i,j)} \log \sigma(\hat{x}_{ui} - \hat{x}_{uj})\]

where:

  • $\hat{x}_{ui}$ is the predicted score for preferred item $i$.
  • $\hat{x}_{uj}$ is the predicted score for non-preferred item $j$.
  • $\sigma$ is the sigmoid function.

BPR optimizes ordering, not absolute rating prediction.

Part 3: Reinforcement Learning and Bandits

Module 8: Why Bandits Matter

Recommenders operate in a feedback loop. What the system shows affects what data it collects. If it only exploits known high-performing items, it may never discover better content.

Multi-Armed Bandits, or MABs, balance:

  • Exploration: trying new or cold-start items.
  • Exploitation: recommending historically high-reward items.

Module 9: Multi-Armed Bandits

Each video, product, article, or item is an arm. Selecting an arm yields a stochastic reward, such as a click, play, watch time, purchase, or conversion.

Algorithm Mechanism Strength
$\epsilon$-Greedy Explore randomly with probability $\epsilon$ Simple baseline
UCB Choose arm with high reward estimate plus uncertainty bonus Principled optimism
Thompson Sampling Sample from posterior reward distributions Strong empirical performance
Contextual bandit Choose arm using user and context features Personalized decisions

Module 10: Contextual Bandits

A contextual bandit observes context $x_t$, selects action $a_t$, and receives reward $r_t$:

\[x_t \rightarrow a_t \rightarrow r_t\]

Unlike full reinforcement learning, it does not model long-horizon state transitions. It optimizes immediate reward under a given context.

Module 11: LinUCB

LinUCB models expected reward as linear in context features.

Disjoint LinUCB

Disjoint LinUCB treats each arm independently and learns arm-specific parameters:

\[E[\text{reward} \mid x_t, a] = \alpha_a^T x_t\]

where:

  • $x_t$ is the context vector.
  • $\alpha_a$ are arm-specific parameters.

Use it when arms have completely distinct feature spaces.

Hybrid LinUCB

Hybrid LinUCB combines global shared features with arm-specific parameters:

\[E[\text{reward} \mid x_t, a] = z_{t,a}^T\beta + x_{t,a}^T\alpha_a\]

where:

  • $z_{t,a}$ are shared features.
  • $\beta$ are shared parameters.
  • $x_{t,a}$ are arm-specific features.
  • $\alpha_a$ are arm-specific parameters.

This shares statistical strength across related arms.

Module 12: UCB and Thompson Sampling

Upper Confidence Bound

UCB selects the arm with the highest optimistic reward estimate:

\[a_t = \arg\max_a \left[ \hat{\mu}_a + c \sqrt{ \frac{\log t}{N_a} } \right]\]

where:

  • $\hat{\mu}_a$ is the estimated mean reward for arm $a$.
  • $N_a$ is the number of times arm $a$ was selected.
  • $c$ controls exploration.

Thompson Sampling

Thompson Sampling samples a reward estimate from each arm’s posterior distribution and selects the arm with the highest sampled value.

Choose arm with largest sampled reward

Observe real reward

Part 4: Bias, Debiasing, and Exploration

Module 13: Position Bias

Position bias occurs because users disproportionately click top-ranked items due to attention and trust heuristics.

Position 1: high observed CTR
Position 2: lower observed CTR
Position 3: lower observed CTR

A model trained directly on clicks may learn “being at position 1 causes clicks,” rather than “this item is relevant.”

Position-Aware Learning

Position-Aware Learning, or PAL, models position as an explicit feature or factor. It separates item relevance from examination probability.

Inverse Propensity Weighting

Inverse Propensity Weighting, or IPW, reweights observed outcomes by the inverse probability that the item was shown:

\[\mathcal{L}_{IPW} = \frac{1}{N} \sum_{i=1}^{N} \frac{c_i}{p_i} \ell(y_i, \hat{y}_i)\]

where:

  • $c_i$ is whether item $i$ was clicked.
  • $p_i$ is the propensity or probability that item $i$ was exposed.
  • $\ell$ is the loss.

Items shown rarely receive larger weights, correcting exposure bias.

Module 14: Selection Bias

Selection bias occurs because training data is skewed toward items previously exposed by the system.

System shows popular items
        |
        v
Users engage with shown items
        |
        v
Model learns from exposed data
        |
        v
System continues showing similar items

Mitigations include:

  • Propensity-weighted offline debiasing.
  • Randomized exploration.
  • Bandit exploration.
  • Counterfactual evaluation.
  • Exposure-aware training.

Module 15: Echo Chambers and Diversity

Over-personalization can narrow user perspectives.

User clicks one topic
        |
        v
System recommends similar topics
        |
        v
User sees less diversity
        |
        v
Feedback reinforces narrow interests

Mitigations:

  • Maximal Marginal Relevance.
  • Category or creator diversity constraints.
  • Exploration through bandits.
  • Freshness boosts.
  • Slate-level objectives.

Maximal Marginal Relevance

Maximal Marginal Relevance, or MMR, selects items that are relevant to the user but dissimilar from already selected items:

\[\text{MMR} = \arg\max_{i \in R \setminus S} \left[ \lambda \text{sim}(i,q) - (1-\lambda) \max_{j \in S} \text{sim}(i,j) \right]\]

where:

  • $R$ is the remaining candidate set.
  • $S$ is the already selected set.
  • $q$ is the query or user representation.
  • $\lambda$ balances relevance and diversity.

Part 5: Set-Level Retrieval

Module 16: Why Item-Level Ranking Is Insufficient

A good recommendation slate is not merely a list of individually relevant items. It should be diverse, complementary, coherent, and grounded.

For example, a query such as “camping gear” should not return ten slight variations of a four-person tent. It should return complementary items: a tent, sleeping bag, portable stove, and headlamp. research

The framework has three stages: research

Stage Purpose Output
Fan-out language-model training Learn property-aligned sub-queries with RL Fan-out model
Supervision synthesis Generate query-to-target-set pairs offline Training data
Diffusive retriever training Map query embeddings to target embeddings Lightweight retriever

The fan-out language models were 4B open-source models: Gemma3-4B and Qwen3-4B. Each generated exactly 10 sub-queries per prompt. The final diffusion retriever has 53.9M parameters and maps a query embedding to a complete set of target embeddings in one non-autoregressive pass. research

Module 19: Set-Level Rewards

Retrieve-for-Train optimizes properties that exist only at the set level. research

Property Meaning Failure prevented
Groundedness Sub-queries correspond to retrievable items Nonsense strings exploiting embedding coordinates
Diversity Sub-queries cover broad semantic breadth Repetitive paraphrases
Alignment Sub-queries remain related to the original prompt Semantic drift

Diversity is measured using the Vendi Score over the full set of sub-queries. research

These rewards act as mutual counter-anchors:

  • Groundedness alone can reward degenerate strings.
  • Alignment alone can reward repetitive paraphrases.
  • Diversity forces useful exploration. research

Module 20: Inference Efficiency

Directly deploying the RL-tuned language model preserves quality but inherits autoregressive latency constraints. The distilled diffusion model generates all target directions simultaneously in one non-autoregressive parallel pass. research

Google reports that Retrieve-for-Train outperformed single-query search, zero-shot expansion, and Best-of-N baselines, while achieving 12 to 20 times faster inference than autoregressive approaches. research

Part 6: LLM-Native Recommendation

Module 21: GenRec

Netflix’s GenRec is an LLM-backed recommendation ranker. It post-trains an internal foundation LLM on Netflix-specific data and objectives, then adds a catalog-aware scoring head.

User history + context + item metadata
                 |
                 v
        Verbalized context
                 |
                 v
        Foundation LLM backbone
                 |
                 v
        Catalog-aware scoring head
                 |
                 v
        In-catalog item scores
                 |
                 v
        Personalized ranking

At inference time, GenRec feeds verbalized context into the model and applies the catalog-aware scoring head. It does not decode assistant messages. The conversational format is primarily a training-time device to preserve language understanding.

Module 22: Two-Phase Training

GenRec uses a two-phase framework.

Phase Purpose Update frequency
Phase 1 Adapt an open-source LLM on proprietary corpora to create a domain-aware backbone Relatively infrequent
Phase 2 Post-train the backbone on ranking-specific data and objectives More frequent

Netflix members generate hundreds of billions of interaction events across surfaces, including views, plays, durations, thumbs up or down, add-to-list actions, and abandons. These logs are converted into single-turn or multi-turn conversations between a user and a recommender.

Module 23: Context Engineering

Naively verbalizing every interaction would exceed the token budget. Netflix treats the context window as a new feature budget and applies context engineering.

The approach is:

  • Prioritize recent, high-signal history.
  • Compress or drop older history.
  • Structure prompts to maximize shared prefixes.
  • Enable better prefix caching.
  • Preserve ranking quality while reducing serving cost.

Netflix reduced context tokens to roughly one-third of the original budget with negligible degradation in offline ranking metrics. Because serving cost is approximately proportional to context length, serving cost fell similarly.

Module 24: Training Objectives

GenRec uses a multi-objective loss combining:

  • A recommendation ranking objective.
  • Language-modeling objectives.
  • Alignment through reward-weighted training.

The ranking objective uses cross-entropy over the catalog or candidate set. Positives are derived from high-value engagements, such as sufficiently long plays or strong explicit feedback, with thresholds and denoising logic.

The language-modeling objective preserves general language understanding and keeps open the possibility of text-generation use cases such as recommendation explanations.

Module 25: Reward-Weighted Alignment

Training only on raw interaction sequences can cause undesirable behavior, such as over-favoring binge-watching or over-focusing on one content type. GenRec weights the ranking loss using signals from separate reward models.

\[\mathcal{L}_{weighted} = w_i \cdot \mathcal{L}_{ranking}^{(i)}\]

where:

  • $w_i$ is a scalar reward-derived weight for example $i$.
  • $\mathcal{L}_{ranking}^{(i)}$ is the ranking loss for that example.

High-value engagements receive larger weights; low-value engagements are down-weighted. Netflix describes this as simpler and more cost-efficient than full reinforcement learning, while noting that RL-style methods such as GRPO produced additional gains but were deferred due to cost.

Module 26: Catalog-Aware Scoring

GenRec’s architecture follows its foundation LLM: a decoder-only transformer trained with next-token-prediction-style objectives, augmented with a catalog-aware ranking head. The scoring head scores only in-catalog items.

For very large catalogs, sampled softmax or candidate sets can make training and inference efficient. This constrains recommendations to the catalog while supporting efficient scoring over large candidate sets.

Module 27: GenRec Results

Netflix reports:

Evaluation Result
Offline ranking GenRec outperformed the production ranker despite fewer input signals and labeled examples
Data efficiency About 40 times fewer Phase-2 labeled examples
Offline MRR About +1.6% improvement
Online test Statistically significant short-term and long-term gains
Traffic coverage About 10% of Netflix traffic

These results apply to Netflix’s production baseline, traffic, catalog, and evaluation setup. They demonstrate the potential of LLM-backed rankers, not a universal guarantee that an LLM ranker will outperform every existing recommender.

Part 7: Continual Learning

Module 28: The Static-Model Problem

Most deployed LLMs are static after training. They have a knowledge cutoff and cannot naturally acquire long-term facts or adapt to new information after deployment.

Two common approaches have limitations:

Approach Strength Limitation
Continue parameter training Can add new knowledge Can cause catastrophic forgetting
In-context learning Fast adaptation without weight updates Knowledge disappears when context ends

Catastrophic forgetting occurs when learning new tasks severely degrades performance on previously learned tasks. In-context learning retains information only within the current context window.

Module 29: The Sleep Paradigm

Google Research’s sleep framework introduces a periodic lifecycle with two states:

  1. Active or wake phase: the model processes inputs and stores temporary information in short-term memory.
  2. Sleep phase: the model pauses new input processing and consolidates short-term memory into long-term parameters.
Active phase
     |
     v
Short-term memory
     |
     v
Sleep phase
     |
     +--> Memory consolidation
     |
     +--> Dreaming / self-improvement
     |
     v
Updated long-term parametric memory

The framework operates within a fixed model architecture and human-defined training rules. During the offline sleep phase, the model unlocks preallocated Mixture-of-Experts memory blocks and updates weights using self-generated practice examples.

Module 30: Memory Consolidation

Memory consolidation transfers fragile short-term context into stable long-term parameters. It uses:

  • Parameter expansion through newly unlocked low-rank experts.
  • A continuum memory hierarchy.
  • Knowledge seeding through upward distillation.
  • On-policy distillation.
  • Learning to imitate using semantic and Levenshtein-distance rewards.
  • Synaptic pruning after consolidation.

The goal is not to copy every short-term detail into parameters. Google describes it as structured, low-rank compression: identify compact directions that preserve on-policy behavior and semantically useful information.

Module 37: Production Checklist

  • Log exposure, position, and propensity.
  • Separate candidate generation from ranking.
  • Use ANN indexes for large catalogs.
  • Apply business and availability filters before ranking.
  • Use multi-task models for competing objectives.
  • Add exploration for cold-start items.
  • Measure diversity and long-term retention.
  • Correct for position and selection bias.
  • Use online experiments before launch.
  • Monitor calibration, coverage, latency, and cost.

Part 9: Limitations and Open Questions

Recommender limitations

  • Feedback loops amplify popularity and exposure bias.
  • Clicks and short-term engagement do not always reflect long-term value.
  • Cold-start items lack interaction history.
  • Multi-objective trade-offs are business-specific.
  • Personalization can reduce discovery and diversity.

Bandit limitations

  • Bandits optimize immediate reward, not necessarily long-horizon utility.
  • Delayed rewards complicate learning.
  • Contextual bandits require accurate context features.
  • Exploration can harm short-term user experience.
  • Propensity estimates can be noisy or biased.

Set-level retrieval limitations

  • Set-level rewards are harder to define than item-level relevance.
  • Diversity can reduce precision if applied too aggressively.
  • Offline RL depends on the quality of the reward function.
  • Distilled retrievers may lose some capability of the original RL policy.

Google notes that groundedness alone can reward degenerate strings, while alignment alone can reward repetitive paraphrases; diversity is needed as a counter-anchor. research

LLM-based ranking limitations

  • LLMs can hallucinate out-of-catalog items.
  • Long context increases serving cost.
  • Raw interaction data can reinforce popularity bias.
  • Reward-weighted training requires careful reward design.
  • Offline gains do not guarantee long-term online improvements.

Netflix notes that off-the-shelf LLMs can over-recommend popular content, hallucinate out-of-catalog items, ignore business constraints, and provide limited personalization.

Continual-learning limitations

  • Continual parameter updates remain risky.
  • Synthetic self-generated data can reinforce model errors.
  • Memory expansion increases model size and infrastructure complexity.
  • Long-context consolidation must preserve both new and old knowledge.
  • Benchmarks may not reflect real production distribution shift.

Google’s sleep framework addresses forgetting through parameter expansion, low-rank memory blocks, distillation, and pruning, but these mechanisms add substantial system complexity.

Final Technical Takeaways

  • Central mechanism: A recommender is a multi-stage decision system: understand intent, retrieve candidates, filter, rank, diversify, serve, and learn.
  • Main architectural insight: Separate candidate generation from ranking; use fast retrieval for scale and high-precision rankers for final ordering.
  • Main learning insight: Bandits balance exploration and exploitation, while contextual bandits personalize decisions using user, item, and session features.
  • Main bias insight: Position and selection bias require explicit mitigation through propensity weighting, position-aware models, randomized exploration, and counterfactual evaluation.
  • Important set-level insight: Optimize the entire slate for diversity, coherence, and complementarity, not merely individual item relevance. research
  • Important LLM insight: LLM-backed rankers need catalog-aware scoring and context engineering to avoid hallucination and control serving cost.
  • Main continual-learning insight: Alternate active interaction with offline consolidation so short-term context can become stable parametric memory without relying solely on a fixed context window.
  • Main trade-off: Exploitation maximizes immediate reward; exploration improves long-term discovery but can reduce short-term engagement.
  • Broader engineering implication: Treat recommendation as a closed-loop decision system, where exposure policy, feedback collection, bias correction, and evaluation are as important as the ranking model. research
