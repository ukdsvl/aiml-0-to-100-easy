Claude Code Masterclass Guide

This masterclass document covers everything required to go from a beginner in Claude Code to building agentic workflows and automated AI systems.

Course Overview & Roadmap

The masterclass is structured into five core modules designed to build practical, production-grade systems:

  1. Foundations: Installation, workspace hosting, permissions, built-in commands, and project context (claude.md).

  2. Customization: Building custom skills, slash commands, lifecycle hooks, and Model Context Protocol (MCP) integrations.

  3. Prompt Engineering: How to structure inputs for optimal, deterministic outputs from Claude Code.

  4. Agentic Workflows: Sub-agents, agent teams, workflow optimization hacks, and 24/7 autonomous deployment.

  5. Real-World Build: Step-by-step end-to-end implementation of real-world projects.

Workspace Environments & IDE Setup

Claude Code can be hosted across several Integrated Development Environments (IDEs) and execution environments:

  • Visual Studio Code (VS Code): The recommended standard IDE. Free, lightweight, and supports the official Anthropic Claude Code extension.

  • Cursor: Popular among developers due to native AI integration. Can become costly as users pay for both Cursor AI usage and Claude usage.

  • Google Anti-Gravity: IDE based on Google’s suite, similar to VS Code. Useful if leveraging Gemini models alongside Claude Code to design custom interfaces.

  • Terminal CLI: Direct execution inside the system terminal. Offers lightweight operation but lacks visual file navigation for beginners.

  • Claude Desktop: Desktop client access, though limited in visual file navigation and deep directory management.

Installing in VS Code / Anti-Gravity

  1. Download and open VS Code or Google Anti-Gravity.

  2. Navigate to the Extensions tab (Ctrl+Shift+X or Cmd+Shift+X).

  3. Search for Claude Code (verify publisher is Anthropic) and click Install.

  4. Authenticate by selecting claude.ai subscription and complete the browser authorization.

  5. Open a target project folder (File > Open Folder) to scope Claude Code to that workspace.

Interface Controls & Permission Modes

Claude Code operates under distinct permission modes to control how aggressively it alters files or executes terminal scripts:

  • Ask Before Edits: Claude prompts for manual user approval before writing or editing any code/file.

  • Edit Automatically (Default): Claude automatically applies file edits without asking per file.

  • Plan Mode: Claude creates a structured step-by-step implementation plan for review before taking action.

  • Bypass Permissions / Dangerously Skip Permissions: Bypasses all confirmation prompts for terminal execution and edits. Enabled in settings via allow Dangerously (recommended for sandboxed environments).

Effort Control

Claude Code includes an Effort setting (Low, Medium, High):

  • Medium is the recommended default balance between speed, cost, and reasoning depth.

Project Memory: The claude.md File

The claude.md file serves as the project instruction manual and long-term memory for Claude Code. It is automatically parsed at the beginning of every session.

The 4 Pillars of claude.md

  1. Product Description: Explains what the workspace/app does and its main objectives.

  2. Tech Stack: Details languages, frameworks, APIs, and external tools used.

  3. Rules & Guardrails: Defines strict requirements, styling guidelines, naming conventions, and constraints.

  4. Folder Structure: Outlines the exact layout of the repository so Claude places files correctly.

Method 1: The 3-Layer Architecture (New Projects)

When starting a project from scratch, setup a structured directory hierarchy:

my-project/
├── claude.md
├── .env                  # API keys and sensitive parameters
├── directives/           # SOPs, instructions, and target objectives
├── decisions/            # Architectural frameworks and decision trees
├── execution/            # Executable code, scripts, and build artifacts
└── tmp/                  # Temporary generation outputs

Method 2: Initializing Existing Repositories (/init)

For pre-existing codebases, run:

/init

Claude Code analyzes the repository hierarchy, code patterns, and dependencies, auto-generating a customized claude.md file.

Module 2: Customization

Skills Architecture

Skills are step-by-step instruction manuals (skill.md) that guide Claude Code through complex procedures (e.g., frontend design, diagram creation, lead extraction).

Directory Layout for Custom Skills

Skills reside in the .claude/skills/ directory:

.claude/
└── skills/
    └── /
        ├── skill.md        # Mandatory: Front matter & structured SOP
        ├── references/     # Optional: Templates, examples, design guidelines
        └── scripts/        # Optional: Executable Python/JS automation scripts

Anatomy of a skill.md File

A standard skill.md requires YAML metadata followed by markdown instructions:

name: Lead Generation System description: Extracts leads via Apify Google Maps Scraper, filters active sites, and scrapes value props.

Prerequisites

  • Apify API token configured in .env
  • Anthropic API key configured for deep scraping analysis

Step-by-Step Execution

  1. Fetch target leads using scripts/lead_generation.py.
  2. Filter results to retain only entries containing both website and phone details.
  3. Perform deep content extraction on home, about, and service subpages.
  4. Export clean dataset to CSV.

Automated Skill Creation & Evaluation Loops

Using skill-creator

Install the official skill creation plugin from the plugin directory or prompt Claude to construct a new skill automatically based on a successful execution workflow.

Evaluation Framework (evals)

To make skills self-improving, implement automated evaluation benchmarks:

.claude/skills//
└── evals/
    ├── eval.json          # Test inputs and benchmark expectations
    └── trigger_eval.json  # Intent recognition test prompts (should trigger vs should not trigger)

Running an evaluation benchmarks the skill performance against raw baseline prompts, outputting pass/fail metrics and format compliance percentages. Iteratively adjust skill.md until reaching a ~100% pass rate.

Custom Slash Commands

Slash commands provide single-line shortcuts to invoke specific skills or procedures directly.

Command Directory Layout

Custom commands are stored in .claude/commands/:

.claude/
└── commands/
    ├── generate-titles.md
    └── lead-gen.md

Command Mapping Example (.claude/commands/lead-gen.md) 

When the user calls /lead-gen, invoke the `lead-generation-system` skill to handle the request. Prompt the user for target niche, location, and result limit.

Invoking /lead-gen directly triggers the targeted skill without writing verbose prompts.

Event-Driven Hooks

Hooks execute automatic scripts at key lifecycle triggers, enforcing global system rules across a project or organization.

Hook Configuration (.claude/settings.json)

Hooks are configured globally within settings.json:

{
  "hooks": {
    "post_response": [
      {
        "type": "command",
        "command": "osascript -e 'display notification \"Claude Code task complete!\" with title \"Claude Code\"'"
      }
    ]
  }
}

Common Lifecycle Triggers

  • Pre-tool Use: Runs validation before Claude executes a script or CLI tool.

  • Post-tool Use: Runs cleanup or formatting after a tool finishes execution.

  • Post-tool Use Failure: Sends alert notifications or triggers diagnostic logging if a script fails.

  • Post-response / Finish: Fires system notifications (e.g., OS alerts, webhooks) when Claude finishes an execution task.
